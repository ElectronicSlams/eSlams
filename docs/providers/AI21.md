# AI21 Labs native Jamba adapter

This adapter is proposed for Core 0.7.1; the package version stays at 0.7.0.
Use `ai21-labs:<exact-model-id>` (`ai21` is the existing registry alias) with
`AI21_API_KEY`. A missing or blank model is an error; Core selects no default
model, alternative provider, or fallback. Unknown model IDs are forwarded
unchanged, subject to the endpoint's own validation.

```bash
# Configuration check only; this does not call AI21.
eslams providers preflight --provider ai21-labs \
  --model jamba-mini-2-2026-01 --arena tic-tac-toe

# These commands make paid inference requests; run only with authorization.
eslams providers preflight --provider ai21-labs \
  --model jamba-mini-2-2026-01 --arena tic-tac-toe --live
eslams run --arena tic-tac-toe --agent ai21-labs:jamba-mini-2-2026-01
```

## Request and response

The [Chat request reference](https://docs.ai21.com/reference/jamba-1-6-api-ref)
specifies `POST https://api.ai21.com/studio/v1/chat/completions`, JSON content,
and `Authorization: Bearer <AI21_API_KEY>`. Core sends the exact requested
`model`, a system message and the shared public act prompt as a user message,
`n: 1`, and `stream: false`. The prompt retains all supplied public history by
default. Only explicit existing operator policies can bound history, output,
or elapsed thinking time. `max_tokens` and `temperature` are sent only when
chosen by the caller. The documented maximum `max_tokens` is 4096; omitting it
leaves the provider's default in force. Core does not insert this as a cap.

The [Chat response reference](https://docs.ai21.com/reference/jamba-api-response)
defines `id`, `choices[].index`, `choices[].message.role/content`,
`choices[].finish_reason`, and `usage.prompt_tokens/completion_tokens/total_tokens`.
Only one assistant text choice at index zero with `finish_reason: stop` is
accepted. `length` is a typed truncation failure even if partial text looks like
a legal action. Missing/unknown completion reasons, tool calls, malformed
choices, body errors, and malformed/duplicate/nonfinite JSON fail closed.

The documented envelope does not supply resolved model identity, so
`locked_model_id` and `model_identity_source` remain null, including if an
undocumented `model` extension appears. Request ID is telemetry, not model
attestation. Missing token counts stay null; totals are not filled from
arithmetic. Cache tokens, reasoning tokens and reasoning-inclusion metadata
remain unknown. Undocumented cost fields and inherited third-party pricing
do not establish a bill; cost remains unavailable. Missing/malformed accounting
does not become complete scoring/publication evidence.

There is no documented hosted reasoning parameter here. `reasoning=auto` and
`disabled` both send no reasoning controls. `enabled`, effort, reasoning budget,
and Gemini thinking budget are rejected before transport. Arena/game labels
never choose a reasoning policy. There is no documented direct Models API in
the reviewed index, so model discovery reports unavailable and preflight keeps
account visibility unverified. Strict catalogue checks remain an opt-in policy;
the inherited registry is advisory and has not been refreshed by this adapter.

## Errors, transport and credential handling

AI21 documents 401, 403, 422, 429, 500 and 503 in the Chat response reference.
Core also maps 400/other 4xx to request rejection, 404 to unavailable,
401 to authentication failure, 403 to permission failure, 429 to rate limiting,
and 5xx to unavailable. Transport errors, timeouts, invalid wire envelopes,
and truncation retain their separate failure classes. Raw error messages are
never exposed. Error-body accounting observations remain quarantined, without
trusted pricing or identity claims.

The shared bounded HTTP transport supplies byte limits, cancellation, operator
deadlines, concurrency and rate admission, invocation-scoped attempt receipts,
and gateway path handling. Default retries and action repairs are zero.
AI21's docs do not establish an error body proving that work was rejected and
unbilled, so this adapter never automatically retries, even with a positive
operator retry allowance. `Retry-After` remains diagnostic. The official
[rate-limit page](https://docs.ai21.com/reference/api-rate-limits) currently
lists 10 RPS/200 RPM for Large and Mini; actual account limits remain provider-owned.

Credential-bearing response IDs and headers are dropped rather than promoted
to identity. Credential echoes in action text or decoded action fields are
rejected. This protects the exact configured key, including keys without a
recognizable prefix, in success, HTTP-error, malformed-body and partial-body
paths. Receipt projection retains only normalized accounting and fixed metadata.

## Fixture provenance and deterministic checks

`tests/fixtures/provider/ai21_chat_completions_success.json` is a redacted,
synthetic instantiation of the non-streaming REST envelope documented in
the Chat response reference above. Field names/nesting follow that reference;
IDs, token counts and action text are test values. It is not a live captured
response or an SDK convenience object. Fault injections preserve that envelope
until the deliberate corruption being tested.

`tests/test_ai21_provider.py` covers exact endpoint/auth/model/payload, full
history, optional operator controls, gateway routing, CLI selection, preflight,
discovery absence, status failures, ambiguous retry rejection, partial/timeout
observations, malformed bodies, missing/malformed usage, unknown identity/cost,
credential echoes including escaped action JSON, and unscoreable Runner failures
without fallback. Every transport call in these tests is stubbed.
